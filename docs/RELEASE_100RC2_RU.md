# ALGA VECTOR 1.0.0rc2 — восстановление полевого RF-тракта

`1.0.0rc2` исправляет критический сценарий, при котором интерфейс был доступен,
но реальный короткий RF-эпизод мог не появиться в SIMPLE MODE.

## Подтверждённые причины полевого отказа

По предоставленным видеозаписям и локальному структурированному журналу
подтверждены два разных режима отказа:

1. В одном сеансе приёмник фактически наблюдал только окно 30,0–32,4 МГц
   (`center=31,2 МГц`, `span=2,4 МГц`). Участки 433/868/915 МГц, 2,4 и
   5,8 ГГц в этот момент не измерялись.
2. В другом сеансе RTL-SDR не открылся. Прежний журнал не разделял отсутствие
   descriptor, занятость устройства, отказ доступа и проблему драйвера.
3. Energy detector мог создать неполный кандидат, но temporal FSM возвращал
   `IDLE/UNKNOWN`; normalizer ошибочно превращал любой `IDLE` в чистый фон.
4. Нормализация выполнялась при запросе UI-снимка. Короткое наблюдение могло
   закончиться до этого запроса и не попасть в Event Bus.

## Что исправлено

### Реальный acquisition

- `READY` больше не означает наличие данных: `last_data_at` и `STREAMING`
  появляются только после успешно принятого физического кадра.
- В snapshot устройства добавлены фактические center/span, source, sequence,
  sample rate, gain mode, число успешных и неуспешных capture.
- Изолированный hardware worker сразу отражает завершённый кадр в device state.
- RTL-SDR open failure разделён на стабильные reason code:
  `DEVICE.RTLSDR_DESCRIPTOR_ABSENT`, `DEVICE.RTLSDR_BUSY`,
  `DEVICE.RTLSDR_ACCESS_DENIED`, `DEVICE.RTLSDR_DRIVER_UNAVAILABLE` и
  общий `DEVICE.RTLSDR_OPEN_FAILED`.
- При старте ошибка реального приёмника немедленно становится incident и
  записью `device.receiver_unavailable`, а не silent failure.

### Аппаратно-достоверный обзор

- Добавлен компактный общий preset `field_priority`: 433 МГц, 863–870 МГц,
  902–928 МГц, 2,4 ГГц и 5,8 ГГц.
- При первом Live-запуске с готовым приёмником preset запускается автоматически.
- План компилируется строго по возможностям текущего hardware. Обычный RTL-SDR
  получает только доступные участки ниже 1,766 ГГц; 2,4/5,8 ГГц честно
  исключаются. Совместимый HackRF может включить верхние участки.
- Последний явно выбранный bounded-план безопасно возобновляется после запуска;
  слишком широкий или долгий план не сохраняется для auto-resume.
- Интерфейс продолжает показывать число окон и минимальное время полного цикла:
  один перестраиваемый приёмник не объявляется одновременным широкополосным
  монитором.

### Детекция и fallback

- В schema v7 добавлен `spectrum.detection_sensitivity`:
  `high`, `balanced`, `low`. Новые и мигрированные полевые профили используют
  `high`.
- HIGH снижает energy/candidate gates, но не ослабляет policy идентификации.
- Любое наблюдение, прошедшее energy gate, синхронно нормализуется и передаётся
  в Event Bus прямо из acquisition path — до следующего UI refresh.
- Неизвестный, одиночный, suppressed или low-confidence эпизод сохраняется как
  `RADIO_ACTIVITY_DETECTED`, а не удаляется и не называется дроном.
- Условие «фон» исправлено: фоном является только сочетание
  `family=BACKGROUND` и `lifecycle=IDLE` без измеренной активности.
- `DATA_HOLD` с зафиксированным RF-изменением остаётся generic activity;
  отсутствие activity при плохом потоке остаётся `SENSOR_UNAVAILABLE`.

### Event Bus и SIMPLE MODE

- Результат публикации содержит `reason_code` и `trace_id`; добавлены счётчики
  attempted/accepted/duplicates/delivery failures/history retention.
- Generic RF-активность считается важной для операторского фильтра и видна при
  включённом «Показывать только важное».
- SIMPLE MODE показывает неподтверждённую активность с низкой уверенностью,
  частотой и понятным ограничением вместо пустого экрана.
- RF-only событие по-прежнему не может создать `LIKELY_DRONE_SIGNATURE` или
  `TARGET_CONFIRMED` без отдельно валидированного classifier record и
  независимого физического подтверждения.

### Полевой debug

- `--live --debug` включает подробный JSONL только для текущего процесса.
- В настройках доступны уровень `DEBUG` и чувствительность детекции.
- Диагностика показывает цепочку DEVICE → CAPTURE → DETECTOR → EVENT BUS → UI,
  последний seq/age, фактическое окно, sample rate, gain и путь к журналу.
- Добавлены события:
  `acquisition.capture_requested`, `acquisition.frame_captured`,
  `acquisition.capture_failed`, `signal_analysis.activity_observed`,
  `signal_processor.event_published`,
  `signal_processor.event_publish_failed`.
- Пошаговый чек-лист: `docs/FIELD_DEBUG_RF_PIPELINE_RU.md`.

## Важные ограничения

- RF-активность не доказывает тип физического объекта. `1.0.0rc2` намеренно
  предпочитает видимый generic fallback ложной тишине, но не выдаёт всплеск за
  подтверждённый БПЛА.
- Обычный RTL-SDR физически не принимает 2,4/5,8 ГГц без совместимого внешнего
  тракта. Программой это ограничение не обходится.
- Последовательный scan может пропустить короткий сигнал между посещениями
  окна. Для одновременного покрытия нужны несколько независимых приёмных
  трактов или аппаратная полоса, соответствующая задаче.
- Направление и расстояние не вычисляются по RSSI одного приёмника.
- Автоматические тесты не заменяют повторный полевой acceptance test конкретной
  связки Windows, USB-драйвера, firmware, антенны и уровня входа.
